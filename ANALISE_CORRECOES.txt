PROBLEMAS IDENTIFICADOS:
================================================================================

1. ❌ AUSÊNCIA DE DEBOUNCING (CRÍTICO)
   ────────────────────────────────────
   
   PROBLEMA:
   - Botões mecânicos não possuem filtro contra instabilidade
   - Quando uma chave é pressionada, ela oscila por ~5-20ms (contact bounce)
   - Cada oscilação gera múltiplas transições que o FPGA lê como pressionamentos
   
   IMPACTO:
   ✗ Notas aleatórias e distorcidas
   ✗ FSM transiciona erraticamente entre estados
   ✗ Comportamento impredizível e não reproduzível
   ✗ Áudio com glitches
   
   CAUSA RAIZ:
   • key_decoder.vhd lê botões diretamente sem filtro
   • piano_uc.vhd verifica "botoes /= 00000000" em instante errado
   • piano_fd.vhd passa botões direto para key_decoder


2. ❌ BUG EM tone_gen.vhd - Divisão por Zero Lógica
   ──────────────────────────────────────────────────
   
   PROBLEMA (linha 31):
   ```vhd
   ELSIF contador = UNSIGNED(divisor) - 1 THEN
   ```
   
   Quando divisor = 0 (nenhum botão pressionado):
   • UNSIGNED(0) - 1 = 131071 (máximo de 17 bits)
   • contador nunca atinge esse valor
   • audio fica congelado em último valor
   
   IMPACTO:
   ✗ Áudio continua oscilando quando nenhuma nota está ativa
   ✗ Após soltar botão, audio não para imediatamente


3. ⚠️  POSSÍVEL METAESTABILIDADE
   ──────────────────────────────
   
   • Múltiplos botões pressionados simultaneamente
   • Sem sincronização no clock, sinais podem estar em estado metaestável
   • Amplifica problemas de bounce


================================================================================
SOLUÇÕES IMPLEMENTADAS:
================================================================================

✅ 1. NOVO MÓDULO: debounce.vhd
   ──────────────────────────────
   
   • Filtra cada bit do vetor de botões independentemente
   • Usa contador de estabilidade: signal estável por ~20ms antes de mudar saída
   • Genéricos:
     - CLK_FREQ: frequência do clock (padrão 50MHz)
     - DEBOUNCE_MS: tempo de debounce (padrão 20ms)
   
   CÁLCULO:
   CONTADOR_MAX = (50_000_000 Hz / 1000) × 20 ms = 1_000_000 ciclos
   Tempo de debounce = 1_000_000 × (1 / 50_000_000 Hz) = 20 ms
   
   FUNCIONAMENTO:
   • Se entrada = saída: zera contador
   • Se entrada ≠ saída: incrementa contador
   • Quando contador atinge CONTADOR_MAX: saída muda


✅ 2. MODIFICAÇÃO: piano_top.vhd
   ────────────────────────────
   
   ANTES:
   • botoes → piano_uc (direto)
   • botoes → piano_fd (direto)
   
   DEPOIS:
   • botoes → debounce → botoes_db_s
   • botoes_db_s → piano_uc (filtrado)
   • botoes_db_s → piano_fd (filtrado)
   
   Adicionado:
   • Instância do componente debounce
   • Signal botoes_db_s para botões debounced
   • Mapeamento de portas no módulo debounce


✅ 3. CORREÇÃO: tone_gen.vhd
   ────────────────────────
   
   ANTES:
   ```vhd
   ELSIF contador = UNSIGNED(divisor) - 1 THEN
       contador <= (OTHERS => '0');
       s_audio <= NOT s_audio;
   ELSE
       contador <= contador + 1;
   END IF;
   ```
   
   DEPOIS:
   ```vhd
   ELSIF divisor = (divisor'RANGE => '0') THEN
       -- Se divisor = 0, nao gera tom
       contador <= (OTHERS => '0');
       s_audio <= '0';
   ELSIF contador = UNSIGNED(divisor) - 1 THEN
       contador <= (OTHERS => '0');
       s_audio <= NOT s_audio;
   ELSE
       contador <= contador + 1;
   END IF;
   ```
   
   IMPACTO:
   • Verifica se divisor = 0 antes de comparação
   • Se divisor = 0, força audio = 0
   • Elimina o problema de audio congelado
