5. COMPARAÇÃO: ANTES vs DEPOIS
═════════════════════════════

  ANTES (sem debounce):
  ├─ Pressionando botão: som aleatório/instável
  ├─ Soltando botão: som não para (audio congelado)
  ├─ Pressionamentos rápidos: comportamento erático
  ├─ Múltiplos botões: transições erráticas
  ├─ Audio: com cliques e glitches
  └─ Experiência: não-funcional
  
  DEPOIS (com debounce + correção):
  ├─ Pressionando botão: som correto (~20ms delay aceitável)
  ├─ Soltando botão: som para imediatamente
  ├─ Pressionamentos rápidos: funciona previsível
  ├─ Múltiplos botões: prioridade mantida
  ├─ Audio: suave e sem distorção
  └─ Experiência: funcional e previsível

8. TROUBLESHOOTING
═══════════════════

  Se houver erros de compilação:
  
  Erro: "Component debounce not found"
        → Adicione debounce.vhd ao projeto Quartus
        → Certifique que está compilando antes de piano_top.vhd
  
  Erro: "Port map mismatch"
        → Verifique nomes de sinais em piano_top.vhd
        → Confirme generics do debounce: CLK_FREQ, DEBOUNCE_MS
  
  Se o audio não parar após soltar botão:
        → Verifique se tone_gen.vhd foi atualizado com a correção
        → Confirme que divisor=0 é tratado corretamente
  
  Se houver delay muito longo (>100ms):
        → Reduzir DEBOUNCE_MS em piano_top.vhd (de 20 para 10)
        → Testar se comportamento melhora
  
  Se houver comportamento errático ainda:
        → Aumentar DEBOUNCE_MS (de 20 para 30)
        → Verificar clock do FPGA: deve ser exatamente 50MHz
        → Verificar qualidade dos botões no hardware


9. AFINAÇÃO FINA
═════════════════

  Para ajustar tempo de debounce:
  
  Em piano_top.vhd, linha 70:
  
  GENERIC MAP (
      CLK_FREQ     => 50000000,     -- Não alterar
      DEBOUNCE_MS  => 20             -- ← Alterar aqui se necessário
  )
  
  Recomendações:
  • 5-10ms:   Botões muito responsivos (pode pegar bounce)
  • 10-20ms:  Ideal para switches mecânicos normais
  • 20-50ms:  Para switches com muito bounce
  • 50-100ms: Para switches de má qualidade
